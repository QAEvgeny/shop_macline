# shop_macline

Демо-витрина магазина техники Apple. Проект показывает основной путь клиента:
каталог -> фильтры -> корзина -> заявка на покупку.

## Как открыть

Откройте `index.html` в браузере двойным кликом.

Отдельный сервер для текущей версии не нужен: все файлы лежат рядом и работают
как статический сайт.

## Что уже есть

- каталог товаров с поиском, фильтрами и сортировкой;
- реальные product-фото в карточках товаров с запасной CSS-иконкой;
- избранное и корзина с сохранением в браузере;
- модальные окна входа и оформления заявки;
- демо-отправка заявки с номером заказа;
- подготовленная отправка заявки в Telegram или email;
- футер с контактами, доставкой, гарантией и документами;
- базовые SEO-теги для поисковиков и превью в соцсетях;
- отдельный слой `api.js`, подготовленный для будущего backend/API.

## Что пока работает в демо-режиме

Товары загружаются из массива `demoProducts` в `api.js`.

Заявка не уходит на реальный сервер. Сейчас она сохраняется в браузере в
`localStorage` под ключом `maclineDemoOrders` и возвращает демо-номер заказа.

Фотографии товаров подключены внешними ссылками с Apple Newsroom/Apple Store.
Для продакшена лучше хранить лицензированные изображения на своем хостинге или
CDN, чтобы сайт не зависел от сторонних ссылок.

Это удобно для показа сайта, но для реального магазина следующим шагом нужно
подключить backend.

## Отправка заявок в Telegram или email

Настройки лежат в `config.js`.

По умолчанию включен режим:

```js
orderTransport: "demo"
```

В этом режиме заявка сохраняется только в браузере.

### Telegram

Чтобы отправлять заявки в Telegram, в `config.js` нужно поставить:

```js
orderTransport: "telegram",
telegram: {
  botToken: "ВАШ_BOT_TOKEN",
  chatId: "ВАШ_CHAT_ID"
}
```

Важно: хранить Telegram bot token в браузерном коде небезопасно для настоящего
сайта. Для реального магазина лучше сделать backend-роут `/orders`, а уже он
будет отправлять сообщение в Telegram. Текущий вариант подходит для локального
демо или закрытого показа.

### Email

Есть два варианта.

Первый: email-webhook, например Formspree, Getform, Web3Forms или свой backend:

```js
orderTransport: "email",
email: {
  endpoint: "https://example.com/order-webhook",
  to: "orders@macline.ru"
}
```

Второй: без webhook. Тогда сайт откроет письмо в почтовом клиенте пользователя:

```js
orderTransport: "email",
email: {
  endpoint: "",
  to: "orders@macline.ru"
}
```

Этот способ не отправляет письмо автоматически. Пользователь должен сам нажать
кнопку отправки в своей почтовой программе.

## Где подключать настоящий API

В файле `config.js` есть настройка:

```js
apiBaseUrl: ""
```

Когда появится сервер, туда можно будет поставить адрес API, например:

```js
apiBaseUrl: "https://api.macline.ru"
```

После этого функции `getProducts()` и `createOrder()` начнут обращаться к
серверу по адресам:

- `GET /products` - получить товары;
- `POST /orders` - создать заказ.

## Рекомендуемые следующие шаги

1. Получить свои лицензированные изображения и перенести их в папку `assets`.
2. Создать backend-роут для заявок, чтобы не хранить секреты в браузере.
3. Подключить CRM или таблицу заказов.
4. Создать простую админку для изменения товаров и заказов.
5. Подключить базу данных.
6. Выложить сайт на хостинг и привязать домен.
7. Добавить оплату и реальные условия доставки.
